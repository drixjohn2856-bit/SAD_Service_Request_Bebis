# ICT Service Request System

A browser-based service request dashboard for the SAD activity. It uses Supabase Authentication and a `service_requests` table for persistence.

## Setup

1. Create a Supabase project.
2. Run the SQL below in the Supabase SQL Editor:

```sql
create table public.service_requests (
  id bigint generated by default as identity primary key,
  requester_name text not null,
  department text not null,
  category text not null,
  description text not null,
  priority text not null check (priority in ('Low', 'Medium', 'High')),
  status text not null default 'Pending' check (status in ('Pending', 'In Progress', 'Completed')),
  user_id uuid not null references auth.users(id),
  created_at timestamptz not null default now()
);

alter table public.service_requests enable row level security;
create policy "Authenticated users can manage requests"
  on public.service_requests for all to authenticated
  using (true) with check (auth.uid() = user_id);
```

3. The project URL and publishable key are configured in `js/supabase.js`.
4. Serve this folder with any static server, then open `login.html`.

## Features

- Supabase email/password login and registration
- Authenticated dashboard with session protection and logout
- Create, read, update, and delete service requests
- Pending default status for new requests
- Search by requester or description
- Combined status and priority filters
- Dashboard totals for all request statuses
